## 상세

1. GitHub 브랜치 동기화.
   local과 origin은 main·develop 모두 일치한다. 두 브랜치는 서로 갈라져 있다.
   develop 전용 커밋 31개는 2026년 7월 이후 홈페이지 개편, ESG 문서, 콘텐츠 작업 전부다.
   main 전용 실질 커밋은 `b43e937`(스케줄 이벤트 추가·번역 키 수정, 2025-10-22) 하나이고 나머지 둘은 머지 커밋이다.
   `deploy.sh`가 develop을 pull 하므로 develop이 사실상 소스 오브 트루스다. main은 2025-10-22 이후 멈춰 있고, `b43e937`이 수정한 `src/pages/Schedule.jsx`는 develop의 정보구조 개편에서 삭제돼 현재 아키텍처에 없다.
   reconcile 방법은 main을 develop에 머지하되 `Schedule.jsx`의 modify/delete 충돌을 develop의 삭제로 해소해 develop 트리를 보존하고, 머지 커밋 생성 뒤 main과 develop을 같은 커밋으로 맞추는 것이다. 히스토리 재작성·강제 푸시는 하지 않는다.

2. 주장 감사 반영본 라이브 배포.
   `35f4ffa`(주장 감사: 웹사이트 4개 언어 + 공식 문서 4종 + 메타)는 2026-10-08 배포 승인을 받았으나 자동 승인 가드가 원격 `deploy.sh` 실행을 막아 배포 여부가 확인되지 않았다. 2026-10-05 확인 당시 라이브 빌드는 2026-07-06판이었다. 과장 문구가 수정 전 상태로 공개되고 있을 가능성이 있다.
   실행은 사용자가 `! sshpass … './deploy.sh'`를 직접 돌리거나 Bash 권한 규칙을 추가하는 방식이다. 완료는 라이브 컨테이너의 asset 해시가 로컬 dist와 일치할 때다.

3. 자동배포 webhook 복구.
   `webhook-8085.cjs`가 미실행·미영속(systemd/cron 없음)이다. `verifySignature()`는 정의만 돼 있고 호출되지 않아 서명 검증이 없다. secret이 저장소에 하드코딩돼 있고 엔드포인트가 평문 HTTP다.
   복구 순서는 포트 8085 점유 정리, 서명 검증 활성화, secret 교체, systemd 영속화다. 서버 변경은 사용자 승인 뒤 진행한다.

4. 스페셜티 강사 가이드 v0.1 수치 확정.
   `MOBA_해양ESG리더_스페셜티_강사가이드_v0.1_20261009.pdf`의 과정명(해양 ESG 리더), 수강 전제(다이브마스터 이상), 지도 비율(1:4), 최대 수심(18m), 과정 시간은 가안이다. 실제 운영 기준으로 확정이 필요하다.

5. 협력사 명판 디자인.
   가이드에 들어갈 협력사 명판 시안이 아직 없다. #4 확정 뒤 작성한다. PADI 로고는 넣지 않고 표지에 'PADI 발행·보증 아님, MOBA 자체 프로그램'을 명시하는 원칙을 유지한다.

6. 브랜치 운영 정책 확정.
   #1 동기화 이후 배포 브랜치를 하나로 정한다. 선택지는 (a) develop을 단일 배포 브랜치로 두고 main은 릴리스 태깅용으로만 운영, (b) main을 기본·배포 브랜치로 통일하고 develop 폐지다. 결정 뒤 `deploy.sh`의 pull 대상과 webhook 트리거 브랜치를 일치시킨다.
